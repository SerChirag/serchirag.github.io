## Abstract

Generative models have undergone many generations of evolution, from VAEs/GANs to diffusion/flow matching. Along the way, the underlying techniques have become more complicated and various beliefs about what drives strong empirical performance have taken hold. Due to the success of diffusion models and flow matching, one of the more common beliefs is the importance of transforming the noise distribution to the data distribution gradually through many small transformations.

We ask whether this is truly necessary, and take a minimalist approach to designing a competitive generative model. We start with the bare-bones essentials, namely just a training objective and a model. We purposefully make both simple. For the training objective, we choose Implicit Maximum Likelihood Estimation (IMLE), and eschew more complicated alternatives such as variational inference, adversarial training and numerical integration. For the model, we eschew transformers and instead choose a moderately sized convolutional network. Then we judiciously added elements that are truly essential, which surprisingly do *not* include iterative denoising. The result is a single-step parameter-efficient generative model that produces high quality samples at fast speed: it achieves an FID of 2.56 on ImageNet 256 and simultaneously attains good precision and recall.

## Background

### Flow Matching and Diffusion Models

Stochastic interpolant models<d-cite key="ho2020denoisingdiffusionprobabilisticmodels,song2021scorebasedgenerativemodelingstochastic,lipman2023flowmatchinggenerativemodeling,stoc-inter"></d-cite>, which includes diffusion and flow matching models, currently define the state of the art in image generation. They succeeded earlier approaches such as GANs<d-cite key="goodfellow2014generativeadversarialnetworks"></d-cite>, which are unstable to train and prone to mode collapse<d-cite key="mode-collapse-1,mode-collapse-2"></d-cite>, and VAEs<d-cite key="kingma2022autoencodingvariationalbayes"></d-cite>, which train stably but tend to produce blurry, low-fidelity samples.

Their advantage is commonly attributed to how they decompose generation<d-cite key="trilemma,diffusion-beats-gan"></d-cite>. Instead of mapping the prior distribution to the data distribution in one large transformation, they break the mapping into a sequence of smaller, simpler transformations. Each of these transformations is typically carried out by a separate step in the sampling process, and as a result sampling takes many steps to iterate over all the transformations.

### Generating in a Single Step with IMLE

Implicit Maximum Likelihood Estimation<d-cite key="li2018implicitmaximumlikelihoodestimation"></d-cite> takes a direct route: a neural generator maps samples from the prior to data samples in a single pass.

Training such a generator directly is generally difficult because [the likelihood of the data under it is intractable]({{ 'https://arxiv.org/pdf/2607.19332#page=13' | relative_url }}). IMLE provides a workaround, implicitly maximizing that likelihood without requiring it to be known explicitly. IMLE optimizes a likelihood-based objective akin to regression, without the variational bounds and encoders of VAEs, the adversarial training of GANs, or the iterative numerical integration used by stochastic interpolant models.  

Formally, IMLE learns a direct mapping $$f_\theta$$ from a prior $$\pi(\mathbf{z})$$ to the data distribution $$p_\mathrm{data}(\mathbf{x})$$ by minimizing

$$
\theta_{\text{IMLE}} = \arg\min_\theta \; \mathbb{E}_{\mathbf{z}_1, \ldots, \mathbf{z}_m \sim \pi(\mathbf{z})}
\left[ \sum_{i=1}^{n} \min_{j \in [m]} \; d\left( \mathbf{x}_i, f_\theta(\mathbf{z}_j) \right) \right],
$$

where $$d(\cdot, \cdot)$$ is a distance.

To optimize the objective, the IMLE algorithm alternates between two phases. In the **matching phase**, $m$ latent codes $$\mathbf{z}_1, \ldots, \mathbf{z}_m$$ are sampled from the prior and each real image $$\mathbf{x}_i$$ is matched to its nearest generated sample in the set $$\{f_\theta(\mathbf{z}_1), \ldots, f_\theta(\mathbf{z}_m)\}$$. This establishes a coupling between $$\pi(\mathbf{z})$$ and $$p_\mathrm{data}(\mathbf{x})$$. Next, in the **optimization phase**, the parameters $$\theta$$ are updated to bring each generated sample closer to its matched real image.

## Can Minimalism Be Competitive?

This paper asks a simple question: is all of the machinery that modern generative models have accumulated, from elaborate architectures<d-cite key="peebles2023scalable,ma2024sit"></d-cite> to sophisticated sampling schemes<d-cite key="edm,song2022denoisingdiffusionimplicitmodels"></d-cite> and intricate training objectives<d-cite key="song2023consistencymodels,meanflow,zhou2025inductive,frans2024stepdiffusionshortcutmodels"></d-cite>, truly necessary? Rather than add to it, we take a minimalist approach: we start from the simplest generative model we can, IMLE, and add only the components that prove essential. In line with the same minimalist philosophy, we use a ConvNeXt-based architecture<d-cite key="liu2022convnet2020s"></d-cite> rather than the transformer-based ones that now dominate. We identify one improvement to each of IMLE's two phases.

## Improvements to IMLE

### Optimization Phase: Supervising Every Stage

#### An Alternative View of Diffusion/Flow Matching Models

Stochastic interpolant methods are commonly understood to perform iterative denoising. At test time, that network is applied repeatedly to convert pure noise into a generated sample. Consider an alternative view of these models under a deterministic sampler (like DDIM or Flow Matching models). Rather than viewing the model as one instance of the denoising network, we unroll the iterations of the sampler and view the model as their composition, $$h_\theta = g^1_\theta \circ \cdots \circ g^T_\theta$$, where $$g^t_\theta$$ is the update applied at iteration $$t$$. This allows us to view the reverse process as a single compositional model $$h_{\theta}$$, that maps a sample from the prior $$\mathbf{x}_T$$ to a data sample $$\mathbf{x}_0$$. Under this view, each $$\mathbf{x}_{t-1} = g^t_{\theta}(\mathbf{x}_t)$$ is an intermediate layer of $$h_{\theta}$$. 


Read this way, the training objective reveals something specific. SI methods supervise the denoising network's prediction at every time step, with equal weight applied to all steps, so every intermediate layer of $$h_\theta$$ receives a direct training signal. We call this per-stage supervision, and we hypothesize that the sample quality of many-step models stems from it rather than from iterative sampling itself.

#### Adapting Multi-Stage Supervision for IMLE

The IMLE generator can also be seen as a prior-to-data network composed of stages, only executed in a single forward pass rather than through iterative sampling. We build it as a stack of upsampling blocks, $$f_\theta = f_{\theta^{L}} \circ \cdots \circ f_{\theta^{1}}$$, in which each stage operates at a progressively higher resolution. This recasts IMLE in a form similar to the diffusion construction, with each stage $$f_{\theta}^{l}$$ now analogous to $$g^t_\theta$$, only indexed by resolution rather than noise level.

In existing IMLE methods<d-cite key="vashist2024rejectionsamplingimledesigning,adaptiveIMLE"></d-cite>, the loss is computed only at the final output, which directly supervises only the last stage. We address this by supervising every stage directly, at the resolution at which it operates. Concretely, we add a per-stage output head so that each stage outputs an image at its own resolution, and obtain its target by downsampling the real image.

### Matching Phase: Making Matching Robust

#### Outliers from Randomness in Sampling

For the IMLE algorithm, the model distribution changes during training, so the matching between model samples and ground truth data points needs to be recomputed. Due to randomness in the sampling, there may be no samples drawn from a mode of the model distribution, and as a result, a ground truth data point that can otherwise be explained by that mode would not be well matched. Note that this is different from mode collapse: the poor matching results from randomness in the sampling, not a deficiency in the model distribution.

#### A Robust Loss

The standard squared $l_2$ loss lets these mismatches dominate the mean loss. In essence this is a problem of outliers: a small number of large-residual mismatched pairs contribute disproportionately to the mean loss compared to a much larger pool of well-matched pairs.

The classical remedy in robust statistics<d-cite key="barron-robust"></d-cite> is to replace the squared $l_2$ loss with a function that grows sub-quadratically in the residual, so that a mismatch has less influence and the well-matched pairs dominate the update. Empirically, we find that Geman-McClure loss works best in our case.

### Putting It All Together

We call the resulting method <b>ROMS-IMLE</b>, short for <b>Ro</b>bust <b>M</b>ulti-<b>S</b>tage Implicit Maximum Likelihood Estimation. We ablate our contributions on Oxford Flowers<d-cite key="oxford-flowers"></d-cite> dataset (1000 images $256 \times 256$).

    });
  })();

  // Each clip is attached only while it is near the viewport. The videos
  // therefore carry no autoplay and preload="none": both loading and playback
  // are driven from here, so a clip that is far off-screen holds no buffer and
  // no decoder. They also fade in from an empty background, so frame 0 is
  // blank white and each one carries a poster to stand in until it plays.
  (function () {
    var vids = [].slice.call(document.querySelectorAll(".video-block video"));
    if (!vids.length) return;

    function attach(v) {
      var s = v.querySelector("source");
      if (!s || s.getAttribute("src")) return;
      s.setAttribute("src", s.getAttribute("data-src"));
      v.load();
    }

    // Detaching the source and reloading is what actually frees the buffered
    // media; pausing on its own keeps everything resident.
    function detach(v) {
      var s = v.querySelector("source");
      if (!s || !s.getAttribute("src")) return;
      v.pause();
      s.removeAttribute("src");
      v.load();
    }

    if (!("IntersectionObserver" in window)) {
      vids.forEach(function (v) { attach(v); v.play().catch(function () {}); });
      return;
    }

    // Play only what is on screen.
    var playing = new IntersectionObserver(function (entries) {
      entries.forEach(function (en) {
        var v = en.target;
        if (en.isIntersecting) { attach(v); v.play().catch(function () {}); }
        else if (!v.paused) { v.pause(); }
      });
    }, { rootMargin: "100px 0px", threshold: 0.01 });

    // Keep a wider band loaded, so scrolling back to a clip does not restart
    // it from a cold fetch. Anything outside that band is released.
    var resident = new IntersectionObserver(function (entries) {
      entries.forEach(function (en) {
        if (en.isIntersecting) attach(en.target);
        else detach(en.target);
      });
    }, { rootMargin: "1200px 0px", threshold: 0 });

    vids.forEach(function (v) {
      var s = v.querySelector("source");
      if (s && s.getAttribute("src")) {
        s.setAttribute("data-src", s.getAttribute("src"));
        s.removeAttribute("src");
      }
      playing.observe(v);
      resident.observe(v);
    });
  })();
</script>
